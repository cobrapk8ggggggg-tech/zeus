# خدمة مشاريع ZEUS

هذه خدمة تنفيذ مستقلة تستعمل **Codex app-server 0.163.0** الفعلي عبر JSON-RPC. واجهة المحادثة وعارض Markdown وبطاقات الأدوات في iOS من المصدر الأصلي المثبت لـOpenMinis. النموذج ليس جزءًا من التطبيق ولا يأتي مع مفتاح مجاني.

## التشغيل

من جذر المستودع:

```sh
docker build -f Runtime/Dockerfile -t zeus-project-agent .
docker volume create zeus-project-data
# أنشئ رمزًا مستقلًا وضعه في متغير ZEUS_API_TOKEN دون نشره في المستودع.
docker run --name zeus-project-agent --restart unless-stopped \
  --env ZEUS_API_TOKEN --env ZEUS_PUBLIC_URL \
  --publish 8080:8080 --volume zeus-project-data:/data zeus-project-agent
```

عند استخدام وكيل شبكي محلي بشهادة خاصة يمكن تمرير حزمة الثقة إلى البناء:
`--secret id=proxy_ca,src=/path/to/trusted-ca-bundle.crt`.
لا تعطّل التحقق من TLS.

ضع الخدمة خلف HTTPS. في إعدادات Zeus ← المشاريع والبيئات أدخل عنوانها ورمز الربط. بعدها افتح «حساب محرك Codex والنماذج» وسجّل عبر رمز جهاز ChatGPT أو مفتاح OpenAI API الخاص بك. يجري جلب النماذج من المحرك؛ توافرها وحصتها يتبعان حسابك. تسجيل المفتاح لا يثبت وحده وجود رصيد.

## ما يستمر بعد إغلاق الهاتف

المشروع موجود في `/data/workspaces/ID` بفرع Git مستقل. قاعدة SQLite تحفظ المهمة وخيط Codex والأحداث قبل إرسالها. الهاتف يقرأ الأحداث من آخر مؤشر؛ انقطاع HTTP لا يلغي العامل. تتوقف المهمة عند الحاجة إلى إجابة أو انتهاء المهلة/الحصة أو عائق حقيقي. افتراضيًا المهلة ساعتان ومحاولات إصلاح التحقق ثلاث؛ الـAPI يسمح حتى 24 ساعة و10 محاولات. هذه حدود تنفيذ، وليست وعدًا أن كل مهمة تحتاج هذا الوقت أو ستنجح.

عند إعادة تشغيل الخادم تحفظ الملفات والخيط وتصبح المهمة الجارية «متوقفة» ليفحصها المستخدم ويستأنفها صراحة؛ لا نعيد إجراء كتابة مجهول النتيجة تلقائيًا. أدوات الهاتف وتبويباته المباشرة لا تظل متاحة بعد أن يوقف iOS التطبيق.

الموافقات تظهر داخل صفحة المهمة. السياسة تُنقل لمحرك Codex: غير الموثوق، وعند طلب إجراء مؤثر، ودون طلب موافقة. العمليات الداخلية التي لا يصدر المحرك طلب موافقة لها، مثل القراءة، ليست طلبات منفردة في هذه الواجهة. الأسئلة تدعم الخيارات الدائرية والإجابة النصية.

## المشاريع والتحقق

يمكن إنشاء مشروع أو استنساخ مستودع GitHub/GitLab/Bitbucket HTTPS. استخدم ربط GitHub للمستودعات الخاصة. حدد أوامر تحقق فعلية مناسبة للمشروع؛ إذا لم تحددها تبقى النتيجة «تحتاج إعداد التحقق» ولا تُعرض مكتملة. بعد نهاية دور الوكيل تشغّل الخدمة تلك الأوامر مستقلة، وتعطي الفشل الفعلي للوكيل ليصلحه ضمن الحد المحدد.

Codex يوفر قراءة الملفات والتحرير وعمليات Git والطرفية وأدوات MCP. المهارة المرفقة تلزمه متابعة SHA ومعرّف GitHub Actions وقراءة السجلات والنتائج. يحتاج بناء iOS ومحاكاته إلى عامل macOS، ويمكن تشغيلهما عبر GitHub Actions؛ حاوية Linux لا تتضمن Xcode. يجب إضافة workflow ملائم للمشروع المستهدف ومنح حساب GitHub صلاحية Actions. نجاح إرسال workflow لا يساوي نجاح البناء.

تضم الصورة Chromium وPlaywright MCP 0.0.83، ويُضاف خادم `zeus-browser` تلقائيًا لمحرك Codex. يستطيع الوكيل تشغيل مشروع الويب والتنقل فيه وإدخال البيانات وفحص DOM والشبكة والكونسول والتقاط الصور. هذا متصفح الخادم المستقل؛ لا يحمل جلسات الهاتف تلقائيًا. الإصدار المثبت يعيد ملفات snapshot مرتبطة ويستعمل `target` للتفاعل؛ المهارة واختبار البروتوكول يطابقان مخططه الفعلي. اختبار الحاوية يملأ نموذجًا ويضغط زرًا ويفحص النتيجة وملف PNG الفعلي، دون استعمال نموذج ذكاء اصطناعي.

## الإضافات

الدليل يستخدم مستودعات `openai/plugins` و`railwayapp/railway-skills` و`vercel/vercel-plugin`. يثبت ملفات المهارات الأصلية وأصولها بمراجعة Git محددة في خادم Codex، ويربط MCP مستقلًا. يمكن استيراد المهارات المختارة إلى الوكيل داخل المتصفح من صفحتها. هذا ليس نقل ارتباطات ChatGPT الخاصة ولا تنفيذ جميع hooks الخاصة بكل منصة.

OAuth مستقل مع PKCE واكتشاف خادم المصادقة وتحديث التوكن. إذا كان المزود لا يسمح بالتسجيل الديناميكي يلزم تسجيل OAuth خاص أو توكن وصول مناسب؛ لا يُختلق client ID. قيم توكنات المزودين مشفرة في التخزين، ولا يرجعها الـAPI؛ يرجع فقط رمز MCP محدودًا بمزود. يخزن Codex مصادقة النموذج بتنسيقه المعتاد في مجلد دائم خاص بالخدمة. النسخ الاحتياطي للخادم يجب أن يشمل `/data` ومفتاح تشفيره.

الخدمة **لمالك واحد** بصلاحية أدوات كاملة داخل حاويته. ليست منصة لاستضافة مستخدمين غير موثوقين في الحاوية نفسها. يلزم عامل/عزل منفصل لكل مالك عند تحويلها لخدمة متعددة المستخدمين. لا يوضع رمز المالك في IPA أو Git.

## Railway المستهدف

الخدمة الرابعة `zeus-project-agent` داخل المشروع الموجود `Cookies Editor Restoration`، مع volume مستقل عند `/data`، وملف إعداد `Runtime/railway.toml` وDockerfile من جذر المستودع. لا تُغيّر الخدمات الثلاث الحالية. أوقف وضع sleep للخدمة كي تظل المهام تعمل. اضبط حدود الموارد وفق حسابك؛ لا يوجد وعد باستضافة أو نموذج مجانيين.

في محاولة التنفيذ الحالية رفض Railway إنشاء الخدمة برسالة `Deploys have been paused temporarily`. لم تُنشأ موارد جديدة ولم يكتمل النشر. يلزم إعادة المحاولة عندما يسمح الحساب/المنصة بإنشاء الخدمات.

## الاختبار

```sh
cd Runtime
pip install -r requirements.txt
python -m unittest -v test_service
```

اختبار الاتصال يستعمل Codex الحقيقي دون إرسال طلب توليد مدفوع. اختبارات دورة حياة التنفيذ تستخدم محركًا مضبوطًا للاختبار، وتتحقق بأوامر shell فعلية من فشل التحقق والانقطاع والاستئناف والموافقات. لا تمثل هذه الاختبارات تشغيل نموذج حقيقي لساعات أو نجاح نشر سحابي.
