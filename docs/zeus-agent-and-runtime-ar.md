# وكيل Zeus: الأدوات والصلاحيات والحجم والبيئة السحابية

هذه التغييرات مبنية على النسخة التي نجح بناؤها في `build/zeus-unsigned-ipa-repair-20261023`، مع الاحتفاظ بواجهات OpenMinis الأصلية ومحرك المحادثة والمزودين والبث وماركداون. إعدادات الوكيل والمحادثات والمزودون مشتركة بين البروفايلات؛ بيانات المواقع منفصلة.

## ما تغير

- أدوات متصفح المستخدم أصبحت عمليات مستقلة مثل `zeus_browser_read` و`zeus_browser_settings`، ولكل أداة معاملاتها المطلوبة وأنواعها وقيمها المقبولة. المحادثات القديمة التي تستخدم `zeus_browser` مع JSON نصي أو كائن متداخل تبقى مقروءة وقابلة للتنفيذ.
- يُتحقق من المعاملات قبل طلب الموافقة أو التنفيذ؛ الأخطاء تذكر الحقل المتوقع. تُطبّع القيم العددية والمنطقية النصية الواضحة فقط، دون إعادة كتابة كود المستخدم أو اختراع وجهة.
- تُنفذ عمليات متصفح المستخدم بالتتابع بدل رفض استدعاءات الوكيل المتوازية عشوائيًا.
- يُحوَّل ناتج JavaScript داخل الصفحة إلى JSON قابل للنقل، مع التعامل مع DOM وBigInt والكائنات الدائرية. تبقى الاستثناءات الفعلية أخطاء، وتُرفق تفاصيلها وإرشادات تصحيح السياق. لا تُعاد إجراءات الكتابة تلقائيًا.
- معرفات عناصر الصفحة فريدة خلال عمر المستند، وتبقى معرفات القراءات السابقة صالحة ما دامت العناصر متصلة والمستند نفسه لم يتغير.
- التنقل العادي يتبع إعادة التوجيه. فحص الكوكيز والتخزين وJavaScript الحساس يبقى مرتبطًا بالموقع الذي استُهدف عند السماح.
- تغيير البروفايل يُبطل سياق المتصفح السابق ويلغي موافقاته المعلقة. قفل الحساب وصلاحيات دوره لا يتغيران بوضع السماح العام.

## الصلاحيات

من **إعدادات الذكاء الاصطناعي ← الصلاحيات** اختر:

1. طلب الموافقة لكل أداة.
2. طلب الموافقة للإجراءات المؤثرة فقط، وهو الافتراضي.
3. تنفيذ الأدوات دون سؤال.

يشمل الاختيار جميع أدوات حلقة الوكيل الأصلية: متصفح المستخدم، متصفح الأتمتة، الملفات، الطرفية وMCP. تظهر الموافقة داخل خلية الأداة الأصلية في المحادثة، بخيارات دائرية للسماح أو الرفض وزر تأكيد. يقدم النموذج `approval_reason` لشرح ما ينوي تغييره؛ التطبيق هو الذي يحدد الحاجة إلى الإذن، ولا يستطيع النموذج منح نفسه الموافقة.

قراءة الصفحة والتبويبات وDOM والكونسول والتوقيتات غير مؤثرة. الكتابة والتنزيل والتنقل والنقر وتغيير الإعدادات وقراءة بيانات الجلسات وأوامر shell وأدوات MCP غير المعروفة تُعامل كإجراءات مؤثرة. أذونات iOS للكاميرا والموقع وغيرها مستقلة عن هذا الاختيار. لكل طلب استمرار مستقل، ويُلغى عند الإيقاف؛ لا يستبدل طلبٌ موافقةَ طلب آخر.

## المتصفحان والسياق

| الأداة | المتصفح |
|---|---|
| `zeus_browser_*` | تبويبات المستخدم الفعلية وبروفايله وبيانات مواقعه في ZEUS Browser |
| `browser_use` | متصفح أتمتة مستقل للوكيل، بحد أقصى ثلاثة تبويبات وجلسات منفصلة |

يُضاف تعريف الهوية والقدرات للوكيل عند بدء كل دور. أدوات المساعدة والإعدادات والبروفايلات تقرأ القيم الحية؛ لا يكتفي الوكيل بوصف ثابت. بطاقات متصفح المستخدم لا تستخدم صورًا أو روابط أو أزرار تحكم من متصفح الأتمتة.

`zeus_browser_settings(action:read)` يعرض مفاتيح الإعدادات الحالية. `set` يغير مفتاحًا واحدًا بقيمة JSON نصية، مثل `advanced.forceDarkWebPages` و`true`، بعد التحقق وفحص النطاق وحفظ البيانات قبل تغيير الحالة الحية. مفاتيح المزودين السرية خارج هذا المسار.

`zeus_browser_profiles` يعرض البروفايلات ويدعم الإنشاء والتعديل والتبديل والحذف ضمن صلاحيات الحساب. تغيير الدور وكلمات المرور والبصمة واختيار صور الجهاز يتطلب عناصر الحساب الأصلية؛ لا يتجاوز الوكيل قفلًا أو يكتب مسارات صور عشوائية. `zeus_browser_interface` يستدعي أزرار المتصفح الأصلية، بما فيها القارئ ومعرض الصور والتقسيم والإعدادات؛ يغلق لوحة الوكيل عند الحاجة لإظهار الواجهة الأصلية. بدء الطباعة أو المشاركة أو الاستخراج لا يعني اكتمال العملية دون تفاعلها المعتاد. دليل `zeus_browser_help` يقرأ أسماء الأزرار وأيقوناتها من تعداد الأزرار الحقيقي، ويشرح التوزيعات والأزرار والقراءة والتنزيلات والترجمة والحجب والتخزين والإعدادات.

فحص الشبكة هنا هو Resource Timing من WebKit، وليس تسجيلًا كاملًا لرؤوس وأجسام طلبات Chrome. لا يستطيع أي مخطط أدوات أن يضمن عدم خطأ النموذج إطلاقًا؛ الهدف منع التنفيذ الغامض وتوضيح التصحيح ومنع تكرار الكتابة غير المؤكدة.

## التعريب والهوية

استُبدلت هوية العرض الافتراضية Minis باسم Zeus، بما يشمل الترويسات وبطاقات العمل والترجمات، مع إبقاء أسماء الأوامر والمخططات وقواعد البيانات التقنية المتوافقة. صُححت التسميات التي كانت تستخدم «خيار» خطأ، ومنها نتائج/متابعة/إصدار/موقع/أحجام الملفات. لا تُغيَّر أسماء الشخصيات المخصصة الأخرى.

## تحليل الحجم

الملف الذي اختُبر أساسًا: تشغيل GitHub رقم `39915241972`، المصدر `8fc3876`.

| العنصر | الحجم التقريبي قبل التنظيف |
|---|---:|
| IPA المضغوط | 57.1 MB |
| مجموع محتويات التطبيق | 159.5 MB |
| الملف التنفيذي الرئيسي | 89.35 MB |
| جدول أسماء الرموز داخل الملف التنفيذي | 49.04 MB |
| مكتبة كشف الصوت | 17.95 MB |
| ملف Alpine المضغوط | 3.98 MB |

تشغيل `39934786469` بنى أول إصدار مُحسّن، ثم استخدم أداة Apple `strip -S -x` لإزالة رموز التطوير المحلية مع إبقاء الرموز المصدرة. انخفض مجموع الملفات من **158,629,765** إلى **97,623,189 بايت** في ذلك البناء، والملف التنفيذي من **88,604,096** إلى **28,154,112 بايت**. IPA الناتج نحو **49.8 MB**. تفاصيل القياس محفوظة في `ipa-size-audit.json` داخل مرفقات البناء. حجم التخزين الظاهر على الجهاز يضيف بيانات التطبيق والجلسات والتخزين المؤقت.

لم تُحذف مكتبات الصوت والفيديو أو الخطوط أو ملفات Linux لتحقيق هذا الخفض. ملف Linux المضغوط وحده صغير نسبيًا؛ قد تكبر بيئته المثبتة لاحقًا بسبب الحزم وملفات العمل، وهذا استهلاك مختلف عن حجم IPA.

## المحلي والسحابي: تصميم المرحلة التالية

الفكرة ممكنة، لكن هذه النسخة لا تعرض مفتاحًا سحابيًا غير موصول. لم يُنشأ خادم ولم تُفعَّل خدمة مدفوعة.

التنفيذ الصحيح يقسم **نقل الأدوات** عن **مزود النموذج**. يبقى مزود الذكاء الاصطناعي قابلًا للتبديل كما هو، ويُضاف نقل تنفيذ محلي/بعيد لأوامر shell والملفات. تبقى أدوات جهاز المستخدم وWebKit محلية، ويرسل الخادم طلباتها إلى الهاتف عند الحاجة وبعد تطبيق الصلاحيات المختارة.

المسار المقترح:

1. خادم Linux مع حاوية مستقلة ومساحة ملفات مستمرة، وواجهة HTTPS موثقة للمهام والإلغاء وبث النتائج. رمز الربط في Keychain؛ لا يُفتح shell عام على الإنترنت.
2. محول نقل يحافظ على أسماء الأدوات والنتائج وأحداث البث الحالية. رفع/تنزيل ملفات المرفقات عند الحاجة، وعدم نسخ بيانات البروفايل كاملة تلقائيًا إلى الخادم.
3. اختبار الإلغاء وإعادة الاتصال والمهام الطويلة وانقطاع الشبكة وتبديل البروفايل قبل إتاحة التبديل.
4. فصل ملفات Linux القابلة للتنزيل عن المحادثات والذاكرة والمهارات وملفات المستخدم. تنزيل حزمة بإصدار وبصمة SHA-256 وتحقق من المساحة، وتثبيت ذري وإمكانية استئناف التنزيل.
5. حذف البيئة المحلية بعد إيقافها وحفظ ملفات العمل. نواة iSH الأصلية تعمل مرة في العملية ولا تدعم إعادة تركيب آمنة بعد الحذف؛ إزالة البيئة وهي تعمل تتطلب إعادة تشغيل التطبيق. لا يُحذف مجلد rootfs عشوائيًا، لأن بعض ملفات العمل قد تعيش فيه.
6. إصدار اختياري خفيف دون حزمة rootfs بعد نجاح النقل السحابي. المكتبات التنفيذية الموقعة داخل التطبيق تُصغَّر بإعادة بناء الإصدار، ولا يمكن حذفها من داخل النسخة المثبتة كما تُحذف حزمة بيانات.

يبقى متصفح الأتمتة الأصلي محليًا أولًا؛ نقله إلى Chromium سحابي يحتاج محولًا منفصلًا، ولا يحدث بمجرد نقل shell إلى خادم.

## خيارات الاستضافة والتكلفة

تحققت المعلومات من الوثائق الرسمية بتاريخ 23 أكتوبر 2026:

- **Cloudflare Containers/Sandbox:** Linux كامل، ضمن Workers Paid الذي يبدأ من **5 USD شهريًا** مع احتساب موارد الحاوية والتخزين وما يتجاوز الحصص. Workers المجاني وحده ليس خادم Linux عامًا. يبدأ احتساب الحاوية عند تشغيلها ويتوقف عند نومها؛ التشغيل المستمر أعلى تكلفة من الجلسات القصيرة. تكلفة استدعاءات نموذج الذكاء الاصطناعي منفصلة.
- **Oracle Always Free:** توجد موارد VM مؤهلة للمجانية، ومنها Ampere A1؛ وثائق الفترة الحالية تذكر ما يعادل **2 OCPU و12 GB ذاكرة** ضمن حصص الاستخدام. التوافر يختلف حسب المنطقة، ويمكن استرداد الأجهزة الخاملة. ليس ضمان استضافة مجانية دائمة لكل حساب.
- **جهاز شخصي قائم:** يمكن استضافة الخدمة على جهازك وربطها اتصالًا خاصًا؛ لا توجد فاتورة VM جديدة، لكن الجهاز يجب أن يبقى متاحًا وتوجد كلفة تشغيله واتصاله.
