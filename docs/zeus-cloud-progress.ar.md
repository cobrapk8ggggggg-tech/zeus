# تنفيذ حساب ZEUS والوكيل السحابي

الفرع: `feature/zeus-cloud-account-20261026`، يبدأ من `e3cc725` دون تغيير فرع الإصلاحات السابق.

توجيه المالك الأحدث: لا حصر صلب عند 2.5 دولار؛ خدمة مقتصدة تنام بعد المهام، دون متصفح أو ترقية تلقائية. البريد وكلمة المرور أولًا، وGoogle مؤجل.

## نُفذ في الشفرة

- Auth SDK مثبت عند 2.55.4، البريد وكلمة المرور وإنشاء الحساب واستعادته، PKCE وجلسة Keychain.
- بوابة دخول SwiftUI مع حركة بسيطة تتوقف بتقليل الحركة والطاقة المنخفضة والحرارة والخلفية.
- ربط صريح لبيانات التثبيت بالمالك، ومنع فتحها بحساب مختلف؛ بيانات الوكيل الحالية process-wide ولا يزعم هذا الإصدار تبديل مالكها حيًا.
- إعدادات الحساب والمزامنة في البروفايل الرئيسي؛ حفظ بيانات المتصفح بكائنات خاصة ذات SHA-256، والتحقق بعد الرفع ثم commit بمراجعة أساس.
- استعادة البروفايلات الدائمة على تثبيت جديد قبل فتح المتصفح، مع حفظ المعرفات وكتابة الفهرس أخيرًا. لا استعادة تلقائية فوق بيانات موجودة متعارضة.
- لا تنظيف محلي حتى الآن؛ نقل الوكيل والأسرار والملفات الكبيرة ما زال قيد التنفيذ ولا يعلن محفوظًا.

## نُفذ في الخدمات

- طبقت migration `zeus_account_checkpoints` في Supabase: RLS، صلاحيات محددة، checkpoint transaction من نوع SECURITY INVOKER، وحاوية خاصة immutable سقف ملفها 8MiB.
- اختبار فعلي على القاعدة، داخل transaction تُلغى: عزل حسابين ورفض إعادة تعيين الملكية، CAS، عدم تكرار العملية، رفض manifest غير صالح؛ اجتاز.
- Supabase security advisor: لا ملاحظات بعد التغيير.
- Railway: الخدمة الرابعة فارغة وحدودها 0.5GB/0.25CPU والنوم معدة. لم ينشر خادم أو متصفح.
- Atlas: cluster مجاني موجود؛ لم توصل به بيانات المستخدم بعد.

## التحقق

- فحوص Python/C السبعة لمصدر OpenMinis والمحوّلات وiSH اجتازت بعد التعديلات.
- اختبارات Swift الجديدة تتحقق من الملكية والتلف والمسارات والاستعادة وفشل الكتابة؛ تنتظر بناء macOS.
- لم يختبر تسجيل مستخدم حقيقي أو تسليم بريد تأكيد بعد، ولم يعلن بناء iOS ناجحًا قبل CI.

## متابعة التنفيذ

1. بناء iOS وتصحيح مشاكل الترجمة واختبار الواجهة والاستعادة.
2. نسخ ملفات الوكيل والأسرار بمعرفات ثابتة وقائمة تغطية واضحة، ثم نقل يمكن استئنافه وتنظيف متحقق منه.
3. API وworker مقتصدان مع Atlas وتخزين Supabase، دون Chromium أو Playwright، مع PTY وبث محفوظ.
4. ربط المحادثة الأصلية بالهدف السحابي، واختبارات الانقطاع والنوم والاستعادة بعد reinstall.
5. إعداد Redirect URL الذي لا تعرض أدوات Supabase تعديلَه، واختبار البريد الفعلي. لا حاجة لإعداد Google في هذه المرحلة.
