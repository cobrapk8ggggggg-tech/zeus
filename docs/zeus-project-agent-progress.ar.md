## حدود التنفيذ

إعدادات الذكاء الاصطناعي والمشاريع والمزودون مشتركة بين البروفايلات، وبيانات المواقع معزولة. تستعمل المحادثة وعرض Markdown والبث واجهات OpenMinis الأصلية. إغلاق iOS لا يترك أدوات جهازه متاحة، لكن عامل المشروع البعيد يستطيع متابعة عمله المستقل.

كل مرحلة تسجل التنفيذ والاختبارات الفعلية. تجهيز خدمة قابلة للنشر ليس نشرًا، ونجاح build ليس تحققًا من واجهة التطبيق أو تشغيل مهمة سحابية لساعات.

## البنية المستهدفة

واجهة ZEUS ← عميل HTTPS وبث أحداث محفوظ ← مدير مشاريع ومهام ← محرك Codex مع مساحة Git معزولة؛ أدوات GitHub/MCP والخدمات؛ عامل Mac للمهام التي تتطلب Xcode.

اختيار مزود النموذج مستقل عن اختيار محرك الوكيل ومكان التنفيذ. يلزم حساب/مفتاح صالح للمحرك المستخدم. لا يتم نقل ارتباطات ChatGPT الخاصة تلقائيًا.

- اختبار العميل المنقطع يستخدم محرك دورة حياة مضبوطًا للاختبار، مع خادم وعامل وقاعدة بيانات وأوامر تحقق فعلية. لا يُوصف بأنه تشغيل نموذج سحابي لساعات.
- تنزيل الإضافات الفعلي: GitHub، Railway (مهارة)، Vercel (37)، iOS (9)، web (6)، مع حفظ SHA المصدر.
- بناء صورة Docker نجح؛ GitHub Actions تحقق من صحة الخدمة وإصدار Codex وإعادة تشغيل الحاوية وبقاء المشروع في volume، وأن المستخدم الفعلي 10001. التشغيل المحلي كشف صلاحية ملفات المصدر وصُححت؛ تشغيل الصورة محليًا واجه كذلك خطأ daemon منفصلًا، والاختبار نفسه اجتاز على GitHub Actions.
- بناء iPhone الأول بعد حذف الوسائط نجح؛ فشل تغليف قديم بسبب اشتراط مجلد Frameworks حُذف من هذه النسخة، وصُحح. بناء دمج المشاريع كشف تسمية مُعامل لعارض الأدوات الأصلي، وصُححت. البناء النهائي على الفرع جارٍ.

- فحص ZIP الفعلي: لا FFmpeg أو Silero أو قواميس jieba/hmm؛ مجلد اللغة الوحيد `ar.lproj`. بقيت خطوط الرياضيات ومحرك iSH وصور المواقع وموارد عرض المحادثة.

## حالة Railway

توجيه المستخدم النهائي: **لا مشروع جديد**. المطلوب خدمة رابعة باسم `zeus-project-agent` داخل `Cookies Editor Restoration`، مشروع `d6701de3-85f4-4d14-85d5-701fbf2204cc`، بيئة `ac243ba4-b555-4d1f-a746-82764f2ffef3`، بجانب الخدمات الثلاث الموجودة وبـvolume مستقل عند `/data`.
